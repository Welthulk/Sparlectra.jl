# CGMES Export

`writeCGMESFiles` writes a `Net` as a CGMES 2.4.15 (RDF/XML) delivery
with four profiles:

- **EQ + TP**: buses (`TopologicalNode` with `BaseVoltage`/`VoltageLevel`
  containers), AC lines (`ACLineSegment`), two- and three-winding
  transformers (`PowerTransformer` with two or three
  `PowerTransformerEnd`s), loads (`EnergyConsumer`), machines
  (`SynchronousMachine` with `GeneratingUnit` and, for voltage-regulating
  units, a `RegulatingControl`), external network injections, asynchronous
  machines, static VAr compensators, shunts (`LinearShuntCompensator`), and
  bus links (closed `Breaker`s), each with terminals and topology
  associations. Optional zero-sequence line attributes and harvested
  short-circuit attributes go into the EquipmentShortCircuit part of EQ.
- **SSH**: load and machine `p`/`q`, the slack unit's `referencePriority`,
  voltage-regulation targets, tap steps, and shunt sections.
- **SV**: the current voltage state (`SvVoltage` per bus, `SvPowerFlow` per
  terminal): after a solve the solution, so a re-import can start from it
  (`cgmes_import.start_values: sv`) and validates against it; right after an
  import the start state.

A re-import rebuilds the same electrical model: its power flow matches the
original to solver precision, phase-shifting transformers included. Any
`Net` exports, whatever its source. Every file starts with a provenance
line, `Generated by Sparlectra.jl v<version> on <date>`, repeated as
`md:Model.description` in the profile header; the date is the `created`
timestamp.

```julia
using Sparlectra

net = Net(name = "demo", baseMVA = 100.0)
addBus!(net = net, busName = "B1", vn_kV = 110.0, vm_pu = 1.0, va_deg = 0.0)
addBus!(net = net, busName = "B2", vn_kV = 110.0, vm_pu = 1.0, va_deg = 0.0)
addACLine!(net = net, fromBus = "B1", toBus = "B2", length = 25.0, r = 0.2, x = 0.39)

files = writeCGMESFiles(net; path = "out")
# -> ["out/demo_EQ.xml", "out/demo_TP.xml", "out/demo_SSH.xml", "out/demo_SV.xml"]
```

Transformers: a two-winding transformer exports the full impedance on end
2 (the branch model's to-side voltage base) and the effective turns ratio
in the end `ratedU` values, so the importer reproduces the solved ratio
exactly. A phase shift becomes a single-step linear phase tap changer
whose increment is the shift angle (the solved state, not the tap table).
A winding with ratio-tap machinery (`PowerTransformerTaps`) exports a
`RatioTapChanger` with range, neutral data, and current step; the end
`ratedU` absorbs the residual. Three-winding transformers imported from
CGMES are reassembled into one `PowerTransformer` with three ends and the
original mRIDs when the reconstruction is exact, otherwise the star group
stays two-winding with a notice.

Optional keyword arguments:

- `sc_line_data::Dict{Int,CGMESLineShortCircuit}`: zero-sequence /
  short-circuit data per line index (order of `net.linesAC`) for the EQ
  profile; only supplied values are written. For a net imported from
  CGMES, `cgmesLineShortCircuitData(result)` builds the dictionary from
  the harvested attributes.
- `sc_source::CGMESShortCircuitData`: the short-circuit harvest of a CGMES
  import (`result.shortcircuit`). Machine, injection, and motor attributes
  (x''d, feeder current limits, locked-rotor data) are written back by
  mRID, so a short-circuit evaluation of the re-import reproduces the
  original.
- `zip::Bool`: additionally pack the profiles into `<name>_CGMES.zip`,
  which the importer and the Web UI upload read directly; its path is
  appended to the returned list.
- `created::DateTime`: the `md:Model.scenarioTime` / `md:Model.created`
  header stamp (default: current time); a fixed value makes the output
  byte-reproducible.
- `notices::Vector{String}`: one line per model element the export could
  not carry exactly; without a sink the lines are emitted as warnings.

Example: `examples/cgmes/cgmes_export_demo.jl`.

## Identity and mRIDs on export

The export resolves each object's mRID through structural keys stored in
`net.cgmes_ids`; a key describes what an object is, not what it is
called:

| Key | Object |
|---|---|
| `TN\|<busname>` | `TopologicalNode` of a bus |
| `BV\|<vn_kV>` / `VL\|<vn_kV>` | `BaseVoltage` / `VoltageLevel` per nominal voltage |
| `ACL\|<busA>\|<busB>\|<k>` | `ACLineSegment`; the bus pair is sorted lexicographically, `<k>` numbers parallel lines on the same pair in first-seen order |
| `LNC\|<busA>\|<busB>\|<k>` | `cim:Line` container of that segment |
| `PT\|<busA>\|<busB>\|<k>` | `PowerTransformer` (same pair and `<k>` rules, counted over transformer branches) |
| `PT3\|<busA>\|<busB>\|<busC>\|<k>` | three-winding `PowerTransformer` over its sorted side buses |
| `…\|E1` / `…\|E2` / `…\|E3` | `PowerTransformerEnd` by end number |
| `…\|PTC` | the phase-shift-carrying linear phase tap changer |
| `…\|RTC` | the exported ratio tap changer of a tap-carrying winding |
| `SVC\|<bus>\|<k>` | `StaticVarCompensator` (also with `…\|RC`) |
| `LNK\|<busA>\|<busB>\|<k>` | bus link (`Breaker`) |
| `EC\|<bus>\|<k>` | `EnergyConsumer`; `<k>` numbers the bus's units of one class in first-seen order |
| `SM\|<bus>\|<k>` | `SynchronousMachine`, with `…\|GU` (`GeneratingUnit`) and `…\|RC` (`RegulatingControl`) children |
| `ENI\|<bus>\|<k>` | `ExternalNetworkInjection` (also with `…\|RC`) |
| `ASM\|<bus>\|<k>` | `AsynchronousMachine` |
| `SH\|<bus>\|<k>` | `LinearShuntCompensator` |
| `…\|T1` / `…\|T2` | Terminals by equipment sequence number (T1 = from side) |
| `MODEL\|EQ` / `MODEL\|TP` / `MODEL\|SSH` / `MODEL\|SV` | `md:FullModel` header ids |

- **Imported networks keep their original ids.** The importer records the
  source mRIDs under the same keys, so a CGMES roundtrip writes each object
  with the mRID it arrived with.
- **Everything else is minted deterministically.** For keys without a
  recorded id (programmatic nets, MATPOWER/DTF imports), the export mints
  a uuid5 from the key string and records it on the net, so the same
  structure produces the same ids across runs and machines.

Renaming a component never changes its mRID; renaming a bus does, because
its `TopologicalNode` key and the line keys built from it change. Two keys
resolving to the same mRID (a hand-edited `net.cgmes_ids`) abort the
export with an error naming both keys before any file is written.

## [Export from the Web UI](@id cgmes-export-webui)

The run form's **Export case as CGMES delivery** checkbox writes one
artifact, the combined `<case>_CGMES.zip` with all four profiles, right
after the network is built; runs that do not converge export too (the SV
then carries the start state). The zip is listed with the run's artifacts
and re-imports directly. The result page shows a *CGMES export* row and,
as a warning badge, the export notices.

The checkbox works for every case format; CGMES cases carry their
harvested zero-sequence line attributes along. Service callers use
`export_cgmes: true` in the `start_powerflow_run` request.

## Tap-changer classes

A transformer whose winding carries a typed phase model in the CGMES
regulating-vector convention exports the model's class with its step:
`:symmetrical` as `PhaseTapChangerSymmetrical`, `:asymmetrical` as
`PhaseTapChangerAsymmetrical` (with `windingConnectionAngle`), `:tabular`
as `PhaseTapChangerTabular` with its `PhaseTapChangerTable` and points; a
model that came in as `PhaseTapChangerLinear` goes out as a table (the
linear origin is not reconstructed). `ratedU1` then carries the neutral
ratio and the importer applies the model on top, so the round trip keeps
the model. A branch without a model, or with a model in the from-side
reciprocal convention (DTF, hand-built), keeps the single-step
`PhaseTapChangerLinear` that carries the solved shift exactly. Ratio tap
changers export as `RatioTapChanger` (no table). Each end's magnetizing
admittance is written on its own `PowerTransformerEnd`.

## Scope

Not produced: tap and machine controller wiring (tap changers carry range
and position, not the controller logic), ratio tap tables, and the DC
modeling of a source delivery. Import: [CGMES Import](cgmes_import.md).
